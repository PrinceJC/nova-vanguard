# Nova Vanguard

*100 levels. 20 heroes. One endless challenge.*

A side-scrolling space shooter built with React, HTML5 Canvas and plain JavaScript, with Supabase accounts, cloud saves and server-verified ranked leaderboards, deployed on Vercel.

> Renamed from **Lumi Blaster**. Database tables, storage keys and account IDs are unchanged, so existing players keep their progress.

---

## 1. What you need

| Service | Why | Cost |
|---|---|---|
| **Supabase** project | Sign-in codes, database, row-level security | Free tier is enough to start |
| **Vercel** project | Hosts the game and the two ranked-run API functions | Free (Hobby) |
| **SMTP email provider** (Resend, SendGrid, Postmark…) | Supabase's built-in sender only allows a few emails per hour | Usually free at low volume |
| **SMS provider** in Supabase (Twilio, MessageBird, Vonage, Textlocal) | *Optional:* sign-in by mobile number | Paid per message |

Without an SMS provider, players simply use email. The game shows a clear message if someone tries a phone number.

## 2. Set up Supabase (about 10 minutes)

1. Create a project at **supabase.com**.
2. **SQL Editor** → run both files in `supabase/migrations/`, oldest first:
   - `20261024000000_lumi_blaster.sql` — tables, row-level security, username rules, leaderboards
   - `20261025000000_public_leaderboard.sql` — lets signed-out visitors see the landing-page leaderboard
3. **Authentication → Providers → Email:** enabled. Turn **Confirm email** on.
4. **Authentication → Email Templates → Magic Link:** make sure the body contains the code, for example:
   ```html
   <h2>Your Nova Vanguard sign-in code</h2>
   <p style="font-size:28px;letter-spacing:6px"><b>{{ .Token }}</b></p>
   <p>Or <a href="{{ .ConfirmationURL }}">tap here to sign in</a>.</p>
   ```
   Do the same for the **Confirm signup** template.
5. **Project Settings → Authentication → SMTP Settings:** enter your email provider's SMTP details.
6. *(Optional)* **Authentication → Providers → Phone:** enable it and enter your SMS provider credentials.
7. **Authentication → URL Configuration:** set **Site URL** to your Vercel address (for example `https://nova-vanguard.vercel.app`) and add it under **Redirect URLs**.
8. **Project Settings → API:** copy the **Project URL**, the **anon public** key and the **service_role** key.

## 3. Deploy on Vercel

1. Push this folder to GitHub, with `package.json` at the top level of the repo.
2. In Vercel: **Add New → Project → Import** the repo. The included `vercel.json` sets the build (`node tools/build.js`) and output folder (`public`), so leave those fields alone.
3. **Settings → Environment Variables**, for Production, Preview and Development:

   | Name | Value |
   |---|---|
   | `SUPABASE_URL` | Project URL |
   | `SUPABASE_ANON_KEY` | anon public key |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role key (**server only, never shown to players**) |

4. **Deploy**. If a variable is missing, the game shows a "Server setup needed" screen naming it.
5. Before launch, edit `tools/static/support.html` (support email) and review `privacy.html` and `terms.html`.

## 4. Run locally

The game needs its API functions, so use the Vercel CLI rather than a plain file server:
```bash
npm install
npm install -g vercel
vercel link          # connect to your Vercel project (once)
vercel env pull      # downloads the environment variables into .env.local
npm run build
vercel dev           # http://localhost:3000
```
Add `http://localhost:3000` to Supabase **Redirect URLs** if you want email links to work locally.

## 5. Project layout

```
public/              built site (index.html + icons + legal pages) — generated by npm run build
src/                 game source: engine, levels, bosses, avatars, renderer, audio, network, React UI
shared/              endless-mode rules used by BOTH the game and the server validator
api/                 Vercel functions: config, run-start, run-submit
supabase/migrations/ database schema, access rules, leaderboard functions
tools/               build script, static pages, icons, original sprite generator
tests/               automated tests (see below)
```

Tuning lives in data: `ENEMIES` and `SHOT_PATTERNS` in `src/engine.js`, worlds and level generation in `src/levels.js`, boss attacks in `src/bosses.js`, avatars in `src/avatars.js`, and endless scoring in `shared/endless-rules.js`. **If you change endless rules, bump `VERSION`.** Runs started under the old rules are then rejected with a "refresh the page" message.

## 6. How ranked endless stays fair

- `run-start` creates a server-side run session with a random seed.
- The seed fully determines the enemy schedule, elite placement and drops, so every player faces the same rules.
- The browser records only events (kills, pickups, hits, blasts). `run-submit` rebuilds the schedule, checks every event against timing and firepower limits, and **computes the score itself**.
- Duplicate, cross-account, expired and impossible runs are rejected with a reason. Leaderboard rows can only be written by the server.

## 7. Tests

```bash
npm test             # weapon/elite, endless anti-cheat, API, saves/migration, database (real Postgres via PGlite), all 100 levels
```
Browser tests (`tests/*.py`) use Playwright with a **test-only** fake backend (`tests/fake-backend.js`, built into `tests/test.html` only, never into `public/`).

## 8. Gameplay reference

- **Weapon:** 1 shot → 3 shots (centre + two angled) → 6 shots (three symmetrical pairs). Every elite drops one upgrade. At max power each extra upgrade is worth +1,000 points.
- **Health:** at most 2 health pickups spawn per campaign level, and at most 2 per 5 minutes in endless.
- **Special blast (E / Blast button):** brief charge, then an expanding wave from the muzzle that damages and clears enemy bullets exactly where the ring passes. 14-second recharge.
- **Ranked periods:** daily resets at midnight and weekly at Monday 00:00, Asia/Manila time.
